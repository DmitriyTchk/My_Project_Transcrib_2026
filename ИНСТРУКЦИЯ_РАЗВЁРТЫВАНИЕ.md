# VibeScribe Studio — Инструкция по локальному развёртыванию

**Система:** Windows 11 Pro, Docker Desktop (WSL2), NVIDIA RTX 3060 Ti 8 GB
**Дата:** 01.09.2026
**Архитектура:** полностью локальная, без туннелей (ngrok/localtunnel не нужны)

```
Браузер (localhost:3000)
        │
        ▼
┌─────────────────────┐      ┌──────────────────────────────┐
│  VibeScribe Studio  │ ───► │  faster-whisper-server       │
│  (React + Express)  │      │  (Docker, GPU, large-v3)     │
│  порт 3000          │ ◄─── │  порт 8000                   │
└─────────────────────┘      └──────────────────────────────┘
```

CORS не требуется: все запросы к Whisper идут через серверную часть приложения (серверный прокси).

## Что было исправлено и адаптировано в коде

1. **Исключена ломающая модель** `deepdml/faster-whisper-large-v3-turbo-ct2` (вызывала ValueError и HTTP 500). Теперь везде приоритет — `large-v3`.
2. **Исправлена сборка сервера** (`--format=esm`): раньше `node server.js` падал с ошибкой `require is not defined`.
3. **Автоподключение к Whisper**: если в настройках не указан эндпоинт, сервер сам использует `http://localhost:8000/v1/audio/transcriptions` (или `http://whisper:8000/...` внутри Docker) и ключ `my-secret-token`.
4. **Исправлена обработка data-URI** в `/api/transcribe`.
5. **Тексты ошибок** переписаны под локальный сценарий (без туннелей).
6. Добавлены: `Dockerfile`, `docker-compose.yml`, `start-windows.bat`, `start-whisper.bat`, обновлён `.env.example`.
7. **Исправлен приоритет выбора модели** (обновление от 02.09.2026): эндпоинт `/v1/models` у faster-whisper-server возвращает ВСЕ известные модели (small идёт первой), и приложение по ошибке использовало `small` вместо `large-v3`. Теперь запрошенная модель имеет приоритет — распознавание всегда идёт на `large-v3`.
8. **Обработка больших файлов** (обновление от 06.09.2026): раньше файл любого размера распаковывался в память вкладки браузера (`decodeAudioData`) — файлы 1+ ГБ роняли вкладку с ошибкой Out of Memory. Теперь файлы свыше 50 МБ отправляются на сервер приложения напрямую (бинарно, без Base64), нарезаются серверным FFmpeg на чанки по 45 секунд на диске, и браузер забирает их по одному. Ограничение по размеру файла фактически снято (лекции на несколько часов, видео 1–2 ГБ).
7. **Всё проверено**: TypeScript — 0 ошибок, сборка успешна, сервер запускается, подключение к Whisper и транскрибация чанков со сдвигом таймкодов и приоритет модели large-v3 протестированы.

# Вариант А (рекомендуемый): всё в Docker через docker compose

Оба сервиса (приложение + Whisper) запускаются одной командой и **автоматически перезапускаются** после сна или перезагрузки ПК (`restart: unless-stopped`).

### Шаг 1. Распакуйте проект
Распакуйте архив `VibeScribe-local.zip`, например в `C:\Projects\VibeScribe`.
> Альтернатива: `git clone https://github.com/DmitriyTchk/My_Project_Transcrib_2026.git` — репозиторий уже содержит все исправления (запушены 06.09.2026).

### Шаг 2. Откройте терминал в папке проекта
В Проводнике: откройте папку → адресная строка → введите `cmd` → Enter.
Или: ПКМ по папке → «Открыть в терминале».

### Шаг 3. Убедитесь, что Docker Desktop запущен
Значок кита в трее, статус «Engine running». Если нет — запустите Docker Desktop и дождитесь зелёного статуса.

### Шаг 4. Запустите всё одной командой
```
docker compose up -d --build
```
Первый запуск займёт 5–15 минут: соберётся образ приложения (Node.js + ffmpeg + сборка фронтенда). Образ Whisper у вас уже скачан. Модель `large-v3` (~3 ГБ) скачается при первом обращении **один раз** и сохранится в Docker-томе `whisper-models` (при пересоздании контейнера повторно качаться не будет).

### Шаг 5. Проверьте, что оба контейнера работают
```
docker ps
```
Должны быть два контейнера: `vibescribe-whisper` (порт 8000) и `vibescribe-app` (порт 3000).

### Шаг 6. Откройте приложение
В браузере: **http://localhost:3000**

### Шаг 7. Проверьте связь с Whisper из приложения
В приложении: **Настройки → Настройка локального GPU/Сервера**.
В поле «URL локального сервера ASR» укажите:
```
http://whisper:8000/v1/audio/transcriptions
```
> ⚠️ Важно: именно `whisper`, а не `localhost`! Приложение работает внутри Docker-контейнера, и `localhost` для него — это сам контейнер, а не ваш ПК. Контейнер Whisper доступен во внутренней сети Docker по имени `whisper`. (В Варианте Б, где приложение запускается через Node.js на самом ПК, наоборот — используйте `http://localhost:8000/v1/audio/transcriptions`.)
В поле API-ключа: `my-secret-token`. Нажмите **«Проверить связь»**.
Должно появиться: «Локальный ASR-сервер успешно обнаружен и готов к работе».

### Шаг 8. Тестовая транскрибация
Вкладка «Транскрибация» → выберите пресет **«Privacy Mode (Только GPU)»** (или включите переключатель **Local GPU** в верхней панели) → загрузите короткий аудиофайл → «Начать транскрибацию».

> Первый запуск транскрибации может занять несколько минут — в этот момент контейнер скачивает модель large-v3. Прогресс виден в логах: `docker logs -f vibescribe-whisper`.

# Вариант Б: приложение без Docker (через Node.js), Whisper в Docker

У вас уже установлен Node.js (использовался для npx/ngrok). Whisper по-прежнему работает в Docker.

### Шаг 1. Распакуйте проект (как в Варианте А, шаги 1–3)

### Шаг 2. Запустите Whisper
Двойной клик по **`start-whisper.bat`**.
Скрипт сам проверит Docker, создаст контейнер `faster-whisper-server` с моделью `large-v3`, ключом `my-secret-token` и автоперезапуском. Если контейнер уже существует — просто запустит его.

### Шаг 3. Запустите приложение
Двойной клик по **`start-windows.bat`**.
Скрипт при первом запуске сам выполнит `npm install` и сборку, затем запустит сервер. Окно терминала должно оставаться открытым.

### Шаг 4. Откройте http://localhost:3000 и выполните шаги 7–8 из Варианта А

> ⚠️ Ограничение Варианта Б: на Windows нет ffmpeg по пути `/usr/bin/ffmpeg`, поэтому серверная нормализация аудио будет пропускаться (есть graceful fallback). Для большинства форматов (mp3, wav, m4a, mp4) браузер сам декодирует аудио — это не критично. Для экзотических контейнеров (MKV, AVI) используйте Вариант А.

# После сна или перезагрузки ПК

- **Вариант А:** запустите Docker Desktop — оба контейнера поднимутся автоматически (`restart: unless-stopped`). Если не поднялись: `docker compose up -d` в папке проекта.
- **Вариант Б:** снова запустите `start-whisper.bat`, затем `start-windows.bat`.

# Доступ с других устройств в локальной сети (телефон, планшет)

1. Узнайте IP ПК: `ipconfig` → «IPv4-адрес», например `192.168.1.50`.
2. С другого устройства откройте `http://192.168.1.50:3000`.
3. Если не открывается — разрешите входящие на порт 3000 в Брандмауэре Windows (Панель управления → Брандмауэр → Правила для входящих → Создать правило → Порт → TCP 3000).

# Решение проблем

| Симптом | Причина | Решение |
|---|---|---|
| `docker compose` — «команда не найдена» | Старая версия Docker | Используйте `docker-compose up -d --build` (с дефисом) или обновите Docker Desktop |
| Приложение открывается, но транскрибация падает с HTTP 401 | Не передан ключ | В Настройках приложения укажите API-ключ `my-secret-token`, либо проверьте, что контейнер запущен с `WHISPER__API_KEY=my-secret-token` |
| HTTP 500 от Whisper, в логах ValueError про модель | Запущен старый контейнер с turbo-ct2 | `docker rm -f vibescribe-whisper` (или старый `blissful_hawkin`), затем запуск по инструкции — только `large-v3` |
| Порт 8000 занят | Старый контейнер whisper ещё работает | `docker ps` → `docker stop <имя>` старого контейнера, затем запуск |
| Медленная первая транскрибация | Скачивается модель large-v3 (~3 ГБ) | Это разовая операция, смотрите `docker logs -f vibescribe-whisper` |
| Ошибка GPU в контейнере | Docker Desktop не видит GPU | Проверка: `docker run --rm --gpus all nvidia/cuda:12.0.0-base-ubuntu22.04 nvidia-smi` |
| Приложение «не видит» Whisper («Не удалось подключиться к серверу») | В Docker `localhost` — это сам контейнер приложения | В поле эндпоинта укажите `http://whisper:8000/v1/audio/transcriptions` (Вариант А) или `http://localhost:8000/...` (Вариант Б, приложение на Node.js) |
| Саммари / перевод / советник не работают | Нет ключа Gemini | Это облачные функции, опциональны. Ключ можно ввести в Настройки → Секреты (хранится только в оперативной памяти сервера текущей сессии) |

# Полезные команды

```
docker compose up -d --build   # запуск/пересборка всего (Вариант А)
docker compose down            # остановить всё
docker compose logs -f app     # логи приложения
docker logs -f vibescribe-whisper   # логи Whisper
docker ps                      # список работающих контейнеров
```

**Порты:** приложение — 3000, Whisper API — 8000.
**Ключ API Whisper:** `my-secret-token`.
**Модель:** `large-v3` (единственная корректная для вашего сервера).
